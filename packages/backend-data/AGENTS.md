# Durable-DAV-Router — Backend Data (D1/DAO Layer)

Scope: `packages/backend-data/**`. Parent index: `../../AGENTS.md`.

- All D1 access via DAOs over `D1Queryable`. `BaseDAO` owns exactly one thing: `withRetry` (transient-fault retry). Per-table SQL belongs in the concrete DAO.
- `UserDAO` — `createUser`/`upsertUser`/`getByEmail`/`getById`/`getByCurrentEmail`/`getByEmails`/`getByIds`/`setCurrentEmail`, plus the static `newId`/`newAnchor` generators. `UserEmailDAO` — `register`/`get`/`resolveVerified`/`listByUserId`/`revoke`/`revokeAllVerified`, the address registry. `RouterBackendDAO` — `create`/`createGuarded`/`getByOwnerSlug`/`getById`/`listByOwnerUserId`/`listByBackendUsernameCi`/`countByOwnerUserId`/`update`/`deleteById`.
- **`users.email` is a frozen anchor** (migration 0004). It is the primary key that `router_backends.owner_email`'s `ON DELETE CASCADE` resolves against, so it is never updated; `users.id` is the identity and `users.current_email` the mutable sign-in address. A new account anchors on its own address when free, and on `UserDAO.newAnchor()` (`anchor-<hex>@users.invalid`) when the address is already another account's primary key — so the anchor is **not** guaranteed to look like an address and must never be reported to a client. `UserRow.id`/`current_email` are optional because they exist only once 0004 has run.
- **`owner_user_id` is the ownership key.** `owner_email` is a legacy denormalized copy of the anchor, still written because the foreign key requires it, and 1:1 with the id. `createGuarded` enforces `(owner_user_id, slug_ci)` uniqueness and the quota in one statement; the `(owner_email, slug_ci)` unique index is retained as the FK-side floor.
- Utils: `D1Types` (`D1Queryable`), `D1Utils` (`executeD1WithRetry`, `sleep`), `D1ErrorClassifier` (`isD1ErrorRetryable` + `isMissingSchemaError` fail-closed helper), `UpdateClause` (`buildSetClause`, used by `RouterBackendDAO.update`).
- **D1 predicate rule**: lowercase the _parameter_, never the column. `lower(col)` cannot use an index, so it degrades the authenticated hot path to a full table scan. Every writer stores a lowercased value, so this changes no matching semantics. `test/integration/api/RouterApi.int.test.ts` asserts `EXPLAIN QUERY PLAN` directly — a wrong predicate and a right one return identical rows, so the plan is the only observable difference.
- `owner_email` is `COLLATE NOCASE` (migration 0003) and is lowercased in the DAO before binding, so the invariant does not depend on every caller remembering to normalize.
- `createGuarded` enforces uniqueness and quota in a single statement. The pre-flight `SELECT`s it replaced raced: two concurrent creates both saw a free slug, and the loser surfaced a 500 carrying the raw `UNIQUE constraint failed` text.
- Migrations: `0001_router_init.sql` (baseline), `0002_router_drop_username.sql` (drop `namespaces`, add the `backend_username` cache), `0003_router_backend_owner_email_nocase.sql` (child-only rebuild adding `COLLATE NOCASE`), `0004_router_user_identity.sql` (identity decoupling, purely additive). Integration embeds all `*.sql` via `__INTEGRATION_MIGRATIONS__`; `test/integration/api/UserIdentityUpgrade.int.test.ts` applies 0001–0003, seeds, then applies 0004 and asserts zero row loss, `PRAGMA foreign_key_check` empty, and that an address change leaves id-keyed access intact.
- **Deploy ordering**: apply `wrangler d1 migrations apply DB` **before** deploying the code. 0004 is a hard requirement — `router_backends.owner_user_id` and the `user_emails` registry are queried unconditionally, so a database without it 500s the owner-scoped plane. The `UserIdentityService` fallbacks cover a *pre-0004 row*, not a pre-0004 database.
- **Never rebuild a parent table.** `router_backends.owner_email` has `ON DELETE CASCADE` on `users(email)`, and `DROP TABLE <parent>` fires it. D1 runs every statement in an implicit transaction, so `PRAGMA foreign_keys = OFF` — SQLite's documented escape hatch — cannot be used. Only the child (`router_backends`, which has no children of its own) may be rebuilt. See the note in `0002`.
- Router stores no credentials and runs no cron pruners, so there is no retention/cursor/pagination helper here.
- Layer 2 (L0-only): import only `@durable-dav-router/shared` + `@durable-dav-router/backend-errors`; never `backend-runtime`, `backend-services`, or `apps/*` (enforced by `no-restricted-imports`).
